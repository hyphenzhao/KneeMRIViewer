## 1.3 待拍板：Outerbridge 的上报粒度

**先澄清一个前提**（医生问「训练时是否需要人工标注」）：

- 我们的 Outerbridge **没有训练过**，不需要标注来训练。分级由厚度几何确定性推出：局部基线（周围约 10 mm 可靠软骨的加权平均，两遍估计，病灶不参与自己的基线）→ 缺失比例 → 连通斑块 → 面积/跨层过滤。
- **病灶检测与分区无关**：先在骨-软骨界面网格上找连通斑块（`morph/outerbridge.py::grade_plate`），找到之后才按多数投票归到某个亚区。**所以把上报粒度变粗不会降低检出灵敏度，只改变「这个病灶叫什么名字」**，改动很便宜。
- 标注真正的用途是**验证**。在这一点上医生完全正确：22 个亚区没法靠肉眼逐个评。

**另一个前提**：我们现在用的**就是** MOAKS / Eckstein 的分区（胫骨 cMT/aMT/eMT/pMT/iMT、股骨 MFT/ecMF/ccMF/icMF/pMF 都是 MOAKS 的名字）。问题不是分区不标准，而是**这套采集撑不起这么细的分区**——病例 18 各亚区跨越的原始层数：

| 亚区 | 跨越层数 | 可信度 |
|---|---|---|
| 股骨滑车 MFT / LFT | 11 / 12 | 可信 |
| 股骨内侧中央带 ecMF·ccMF·icMF | 6 · 5 · 5 | 存疑 · 一般 · 一般 |
| 股骨外侧中央带 ecLF·ccLF·icLF | 5 · 5 · 5 | 一般 |
| 胫骨外缘 eMT / 内缘 iLT | 4 / 4 | 一般 |
| 髌骨内/外侧面 | 8 / 6 | 一般 / 可信 |

**建议方案：分级与测量解耦**

1. **上报分级降到软骨板级**：股骨内侧、股骨外侧、胫骨内侧、胫骨外侧、髌骨共 5 个（如需可把滑车单列 = 7 个）。取该板内最重病灶，位置用**文字**描述（「内侧股骨髁中央负重区」），不用亚区代码下断言。这个粒度放射科医生在原图上能确认，因而可以做一致性研究。
2. **亚区层面只报厚度数值**——那是测量不是诊断。细粒度的空间信息交给展开图表达：图显示哪里薄、病灶轮廓在哪，图不对每个亚区下分级断言。
3. **跨层数 < 3 的亚区不出分级**（现在只标「存疑」但仍然出级）。
4. **附录保留**全部 22 个亚区的数值与可选的亚区分级，标可信度，供研究使用。

**要拍板的**：默认粒度取 5 个板 / 7 个（含滑车）/ 维持 22 亚区。

**验证设计**（决定粒度之后才能做）：板级 Outerbridge，2 位读片者 × 约 30 例盲读原图，与算法算加权 kappa。天花板要写进报告：无关节镜对照，读片者本身也不是金标准；I 级需信号信息，本方法不评估。

**实现代价**（真要改时）：`morph/outerbridge.py` 增加板级汇总（`grade_plate` 已返回 `summary`，加一个 `grade` 字段取最重病灶即可）；`report/sources.py::computed_cartilage` 改成输出板级 `grades`；`web/src/pages/report/figures/PlateMaps.tsx` 的分级图按板着色而不是按亚区；附录表不动。约一天。

# 第二部分 · 接入影像模型

## 2.1 开源现状：结论先行

普查了 25 个候选（含 MONAI Model Zoo、nnU-Net 预训练集、TotalSegmentator 系列、各类基础模型）。**除骨与软骨外，只有半月板有真正可下载且许可宽松的权重。** 韧带、肌腱、积液、骨髓水肿、囊肿都没有可用的开源模型——不是"效果差"，是**根本没发布权重**。

| 结构 | 开源权重 | 许可 | 判断 |
|---|---|---|---|
| 骨、软骨 | 有（多个） | MIT / Apache-2.0 | 已有，不需要 |
| **半月板（内/外侧）** | **有** `aagatti/nnunet_knee` | **MIT**，9 类分割，nnU-Net v2 | **可先接，但必须验证**（域差见下） |
| 前/后交叉韧带 | 无 | — | 只能自训；公开的 ACL 数据集（MRNet、Štajduhar）均为**研究限定**，商用不可 |
| 内/外侧副韧带 | 无 | — | **矢状位单序列做不了**，需冠状位 |
| 髌韧带、股四头肌腱 | 无 | — | 自训最容易的一个（对比度高、结构大） |
| 关节积液 / 滑膜 | 无 | — | 矢状位可测髌上囊积液；**MOAKS 积液分级按定义在轴位**，无轴位不合规 |
| 骨髓水肿 | 无权重，但**有 CC0 标注** `OAI-ZIB-BMEL` | 标注 CC0-1.0 | 自训底料最好的一个 |
| 腘窝囊肿 | 无 | — | 主要在轴位诊断，矢状位单序列不可靠 |

**共同的域差问题**：所有可用权重都训练自 **3D 梯度回波（DESS / qDESS，层厚 0.7–1.5 mm）**，而我们是 **2D PD-FSE 3 mm**——层厚差 4 倍、组织对比不同。`aagatti/nnunet_knee` 作者原话是"针对矢状位梯度回波脂肪抑制优化，其他序列的表现尚待探索"。半月板在我们的数据上只占 2–4 层，体部/角移行处部分容积严重。**预期它能跑、能出一个看起来像样的掩膜、而体积系统性错误。所以第一版只用它定位，不报半月板体积。**

**明确要写给客户的一句话**：内外侧副韧带、MOAKS 积液分级、腘窝囊肿，**在矢状位单序列上无论用哪个模型都做不出来**，这是采集协议问题，不是模型问题。——这条正好与第 1.2 节要冠状/轴位图像的请求互为因果。

## 2.2 关键架构决定：模型跑在平台之外

**不把 PyTorch 放进服务端。** 模型作为**离线批处理**运行，输出 NIfTI 标签图落到 `predictions_roots`，由现有 ingest 路径吃进来。

理由：

1. 离线安装包不膨胀——torch 的 CUDA 轮子 800 MB–2.5 GB，会淹掉整个 bundle（现在全部依赖加起来才几十 MB）。
2. nnU-Net / torch 的依赖与许可风险**不进产品**；服务端依赖表不变。
3. 平台本来就是"吃标签图"的设计：`seg/ingest.py` 的 `derive_transform` 会拒绝任何不在该序列网格上的标签图，**白送一道校验**；`adapters/copd.py` 已有"一个序列挂两套分割"的先例。
4. GPU 只在推理机上需要（本机 2× RTX 3080 足够；157 例 × 约 80 s ≈ 3.5 小时）。

**要补的洞**：`README.md` 与 `deploy/config.example.toml` 都承诺了「往 `predictions_roots` 里丢文件即可，不需要改代码」，但**没有任何代码实现它**——`cfg.predictions_roots` 被解析后无人读取，`origin='model'`、`model_name`、`model_version`、`source_root='derived'` 全都没有生产者。这是本轮要补的第一个洞（约 60 行）。

## 验证方式

- S1：假模型端到端——写一个输出固定掩膜的脚本丢进 `predictions_roots`，跑 `mrictl scan`，断言 `segmentation` 多出一行 `origin='model'`、`model_name/version` 落库，报告章节由 `pending` 变为 `model`，护栏不误杀，医师可改该章的分级并能撤销。同时断言**未接模型的章节仍然显示占位、绝不断言正常**（现有不变量）。
- S2：157 例批量推理的合理性报告（每例是否分出内外侧半月板、体积分布、与报告文本「变性/撕裂」的一致性），写进 README；过闸前半月板章节不得进入报告。
- 全程保持：`pytest`（现 181 项）、`integration_check`、`report_figures_check`、`report_views_check`、`browser_check`、`verify_no_cdn.sh` 全绿。
